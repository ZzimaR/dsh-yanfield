# AI 与费用

## 一、模型从哪来

砚田不内置 API Key，也不自己保存凭据。它向 DeepSeek Harness 借两条已注册的路由：

| 路由 | 显示名 | 凭据来源 | 适用 |
| --- | --- | --- | --- |
| `deepseek-account` | DeepSeek 账号登录 | Harness 里已登录的 DeepSeek 账号 | 推荐，零配置；能查余额 |
| `deepseek-official` | DeepSeek 官方 API Key | `DEEPSEEK_API_KEY`（环境变量或 Harness 的模型服务页） | 按量计费；不想在客户端登录账号时用 |

`设置 → 模型服务` 里的「模型路由」分段控件可以一键切换，未就绪的那条会写明原因：

- 账号路由未就绪：`还没有登录 DeepSeek 账号：在 DSH 里登录后即可直接用`
- Key 路由未就绪：`还没有保存 DeepSeek API Key：在 DSH 的模型服务页填写，或设置 DEEPSEEK_API_KEY 环境变量`

插件默认优先使用账号路由。若旧版本的配置指向 Key 路由而 Key 缺失，请求会自动回退到账号路由，不需要手动改。

## 二、模型目录

DeepSeek 内置目录（以 Harness 实际返回为准）：

| 模型 ID | 名称 | 上下文 | 输入 |
| --- | --- | --- | --- |
| `deepseek-flash` | DeepSeek-V4.1-Flash | 1,048,576 | 文本 + 图像 |
| `deepseek-v4-pro` | DeepSeek-V4-Pro | 1,048,576 | 文本 |

- Harness 里新增模型后，砚田打开模型服务页会自动把目录同步进 provider（不需要手动「拉取」）。
- 也可以手动填模型 ID。
- 思考档位：默认 / 关闭 / 轻量 / 深入 / 尽力（对应 `off` / `low` / `high` / `max`），由 Harness 侧执行；思考内容不会写进正文。

## 三、余额

输入框底部的「余额」按钮走 Harness 的账号服务查询已登录账号的余额：

- 读到：显示 `余额 ¥68.87` 这类金额；
- 未登录或读不到：提示先去 DSH 登录；
- 服务异常：提示稍后重试，不会假装成 0。

凭据始终只在宿主侧（`yanfield.db` 与 Harness 凭据存储），不会进入浏览器代码。

## 四、单价与峰谷

插件内置 DeepSeek 官方价目表（元 / 百万 token）：

| 模型 | 时段 | 缓存命中输入 | 缓存未命中输入 | 输出 |
| --- | --- | --- | --- | --- |
| `deepseek-flash` | 高峰 | 0.04 | 2 | 8 |
| `deepseek-flash` | 空闲 | 0.02 | 1 | 4 |
| `deepseek-v4-pro` | 高峰 | 0.30 | 9 | 27 |
| `deepseek-v4-pro` | 空闲 | 0.15 | 4.5 | 13.5 |

- **高峰**：北京时间周一至周五 9:00–12:00、14:00–18:00，且不是法定节假日。
- **空闲**：其余所有时段（含周末、法定节假日全天），价格为高峰的一半。
- 旧模型名 `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 仍按 Flash 计费。
- 官方调价时，更新插件版本即可；也可以在设置里手动改三档单价覆盖内置值。

## 五、费用怎么算

- 每次调用后按 `（输入 − 缓存命中）× 输入单价 + 缓存命中 × 缓存单价 + 输出 × 输出单价` 估算。
- 底部「今日 N tok · 预估 ¥X」是**今日累计**；点开可以看当天每条消息的明细。
- 接口返回真实计费信息时显示接口值；没有则显示「预估」；两者都没有时显示「费用未知」。
- 余额与费用互不影响：余额是账户真实余额，费用是本地估算。

## 六、上下文预算（默认不限）

默认**不设上限**：DeepSeek 的窗口有 1,048,576 tokens，砚田会把大纲、资料、前文尽可能都带上。需要控制成本时可在「设置 → AI 与上下文」里选 96k / 128k / 256k / 512k，或填自定义值。

`0 = 不限` 并不等于无限灌：每次请求会按所选模型的窗口留出约 10% 与输出预留（`单次输出上限`，自动时按 8k）后裁剪最旧的观察记录；如果仍超出窗口，会直接报出「预计需要 X tokens，超过窗口 Y」，而不是静默截断。

## 七、默认的省费行为

| 行为 | 说明 |
| --- | --- |
| 决策轮不思考 | 选工具、写参数是结构化输出，不消耗深度思考 |
| 小任务降档 | 选区改写、800 字以内、或「只改这一段 / 润色 / 改一句」这类指令用轻量思考 |
| 资料整理按需触发 | 只在新建章或正文变化 ≥120 字时才自动整理资料，避免为一句话跑一整趟 |
| 工具回执截断 | 单次读取结果过长会截断并提示分页，避免它在后续每一轮被重复发送 |
| 多步合并 | 提示模型把可并行的读取与多处改动合并到同一轮 |
| 前缀缓存友好 | 稳定资料在前、当前正文与临时任务在后，减少重复前缀，命中率通常 80% 以上 |

参考量级（高峰价、真实调用）：单段润色约 ¥0.03；一章章纲约 ¥0.03–0.17，取决于已有资料多少；纯聊天约 ¥0.004。

## 八、常见疑问

**为什么一次任务显示几十万 token？**
那是整个会话的累计输入（每轮都会重发上下文），不是一次请求。实际计费里大部分命中缓存，单价只有 1/50。

**为什么不同任务价格差很多？**
轮次数量、读了多少资料、写多长，都会影响；章纲这类需要反复读上下文的活更容易贵。

**能更省吗？**
- 空闲时段写作（价格减半）；
- 用「只改第 N 段」这类明确指令，避免模型自己挑范围；
- 长任务拆成几次小任务，减少单次上下文长度。
